## Task 1

### Important

1. **Consent can be borrowed from another user through git.** `SKILL.md:38` and `layout.md:24,78-83` treat `.tech-lead/superdesign-consent` as per-user because it is "git-ignored", but nothing makes sure it is. `.tech-lead/` goes into `.gitignore` only on new work (`SKILL.md:27`), not when resuming an initiative or in a project that ignores only `.tech-lead/scratch/`. The file holds only `consent: yes` and a date, with no identity. If it gets committed, a second contributor's clone has `consent: yes`. In autopilot (`SKILL.md:38`) superdesign then runs without asking them, sending their code and spending credits on their account. Fix: in `SKILL.md:38`, before reading the file, require `git check-ignore -q .tech-lead/superdesign-consent` to succeed and `git ls-files --error-unmatch` to fail. Add `.tech-lead/` to `.gitignore` when it is missing, also on resume. Treat a tracked file as no consent. In `layout.md:80-83`, add a `user: <git config user.email>` line and ask again when it does not match the current user.

2. **No guard on what files and images are sent.** The superdesign skill chooses `--context-file` entries itself. It follows the page's import tree and adds `globals.css`, `tailwind.config` and config/router files, and its INIT.md copies the full source of components, layouts, routes and config (`next.config.*` and similar) into `.superdesign/init/`. It also uploads screenshots and brand images, which become public URLs. Neither `SKILL.md:41-43` nor `layout.md:89` stops `.env*`, key/credential files, config holding secrets, git-ignored files, or screenshots with real user data from being sent. The user never sees the list. The consent covers only "selected project files". Fix: add to `SKILL.md:43` step (1): "Before each generation, list the `--context-file` set and the files to upload to the user (status note in autopilot) and the journal. Never send `.env*`, `*.pem`/`*.key`, credential or secret files, git-ignored files, or images with real user data; cut a config file to its theme lines with `path:start:end`." Give the same rule to the init subagent's brief (`SKILL.md:41`).

3. **The consent text leaves out that data is kept.** `layout.md:89` says what is sent, but not what superdesign keeps. Its SUPERDESIGN.md ("USER REQUEST PASSING") says the user's verbatim request (`--user-request`, up to 16KB) "is shared with SuperDesign and stored server-side to improve generation". Drafts built from the spec and context files also stay on the user's canvas. This is not informed consent about retention. Fix: add to `layout.md:89`: "The user's request is stored by superdesign to improve generation; drafts, uploaded assets and context stay on the superdesign account until deleted there." Also tell the lead not to pass `--user-request` for text that holds secrets or internal data, or to leave it out (it is optional).

### Minor

4. **The unpinned CLI runs with the user's full shell.** `SKILL.md:39,43` and `layout.md:90` use `npx --yes @superdesign/cli@latest`. It runs on every call, with the user's environment variables, tokens and repository, and `--yes` skips the install prompt. Each call resolves `@latest` again, so one flow can mix versions. The spec chose this and the consent text discloses it, so this does not block the task. Suggested spec ruling: resolve the version once per run (`npm view @superdesign/cli version`), record it in the journal and use `@<version>` for the rest of that run.

5. **The standalone check is too loose to verify.** `mockup-prompt.md:26` and `SKILL.md:43` (4) allow "the Tailwind CDN script and the Lucide icon CDN" and "public https images from superdesign" without naming hosts or versions. The Tailwind Play CDN is unpinned third-party JavaScript with no SRI, and it runs whenever anyone opens the committed `mockup.html`. Each open also sends the viewer's IP and a request to those CDNs and to superdesign's image host. The check also says nothing about requests made by scripts (`fetch`, XHR, WebSocket, `<form action>`, `<meta http-equiv=refresh>`, `<iframe>`) in AI-generated inline JS. Fix: name the exact allowed hosts and pinned script URLs. Fail on any other `<script src>`, `<link>` or `<iframe>`, and on inline code that makes network requests.

6. **`.superdesign/` may be committed before the allowlist exists.** `layout.md:201-208` adds `.superdesign/*` / `!.superdesign/design-system.md` only "when superdesign is used", without saying when. The init subagent (`SKILL.md:41`) writes full source dumps to `.superdesign/init/` and the first draft writes `resume.json` with account ids, possibly before those lines exist, and a later broad `git add` commits them. Fix: in `SKILL.md:41/43`, add the two lines before dispatching the init subagent or the first CLI call, and confirm with `git check-ignore .superdesign/resume.json`.

7. **The ban on subagents is only text, and the init exception is unclear.** `SKILL.md:177` puts the never-invoke line in every subagent brief, yet the init subagent (`SKILL.md:41`) is told to follow the skill's INIT.md, and SKILL.md of the skill calls that "`superdesign init`". It is ambiguous whether this counts as invoking the skill, and that subagent could load the whole skill, which sends it to `resume.json` and the CLI. Subagents started by other skills (brainstorming's spec reviewer, `simplify`, `engineering:code-review`) do not get tech-lead's line. Fix: the init brief says "read INIT.md as a file only; do not load the superdesign skill; do not use the shell or the network". Dispatch that subagent without Bash where the harness allows it.

8. **Canvas and preview links go into the committed journal.** `layout.md:134-139` writes them to `journal.md`, which is committed. I assumed preview links might work without login; the source does not say. If they do, anyone who can read the repository can see the design and the spec content in it. Fix: record project and draft ids only, or record links only after confirming they need the account's login.

9. **Consent never expires and cannot be withdrawn.** `layout.md:85` asks once and keeps a yes forever, and autopilot runs on it unattended (`SKILL.md:38`). The text does not say how to withdraw it or that it covers later initiatives in the same clone. Fix: add to the consent text "covers every initiative in this clone; withdraw by setting `consent: no` or deleting the file". In autopilot, post the context-file list from finding 2 as a status note before the first generation.

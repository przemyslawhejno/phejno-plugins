# Project document layout

Every artifact lives inside the project directory, in this hierarchy, unless the user says otherwise.

## Hierarchy

```
docs/
  STATUS.md                     generated: in progress, planned, backlog head, recently done
  backlog.md                    unplanned tasks, follow-ups, parked findings
  standards.md                  project conventions and shared checks
  adr/
    NNNN-<title>.md             architecture decisions
  initiatives/
    YYYY-MM-DD-<topic>/         one folder per piece of work
      spec.md                   requirements, from the user or brainstorming
      mockup.html               when the work is visual
      plan.md                   implementation plan from writing-plans
      ledger.json               plan data: tasks, models, verify commands, done
      journal.md                sessions, rulings, escalations, wave results, closure
      research/                 prior-art, spike and plan-review reports
.worktrees/                     lane worktrees (git-ignored)
.tech-lead/scratch/             spikes, checkpoint logs and temporary files (git-ignored)
.superpowers/sdd/               SDD workspace (git-ignored, managed by SDD)
```

- `docs/STATUS.md`: generated by `status.py --write`. Never edit it by hand.
- `docs/backlog.md`: one line per item, format below.
- `docs/standards.md`: conventions in force (layout, naming, formatter, linter, type checker, test runner, CI). It ends with a `Checks` list of commands, copied into each ledger's `checks`.
- `docs/adr/NNNN-<title>.md`: one decision that shapes the system beyond a single initiative. Number sequentially from `0001`.
- `docs/initiatives/YYYY-MM-DD-<topic>/`: one initiative is one folder. Everything about it is found there, never under `docs/superpowers/`. The date is the day the folder was created.
- `research/`: scout reports (`research/<area>.md`), spike answers, and `research/plan-review.md`.

## State

An initiative's state is derived from its files, so it cannot drift. Checked in this order:

1. A line in `journal.md` starting `Closed:` → `closed`.
2. `ledger.json` present but failing to load or validate → `unknown (ledger error)`.
3. `ledger.json` with every task id in `done` → `done`.
4. `ledger.json` with some task ids in `done` → `in progress`.
5. `ledger.json` with none done → `planned`.
6. `spec.md` → `specified`.
7. Otherwise (folder with `journal.md` only) → `proposed`.

Never record state anywhere else; change the files instead.

## Journal

`journal.md` is the initiative's memory for later sessions. Entries are short and dated, newest last.

Session, written before a turn ends with work stopped:

```
## 2026-11-12 session
Done: <what was done>
Open: <what is open>
Next: <what comes next>
```

Wave, appended by `ledger.py checkpoint --mark` (never write it by hand):

```
## 2026-11-12 wave 2
Tasks done: 3, 4
<lines of SDD's progress.md containing "Ruling:" or starting with "Attempt:", not yet copied>
```

Plan review, gate and re-gate:

```
## 2026-11-12 plan review
Rounds: 2. Applied: <findings>. Rejected: <finding> — <reason>.
Report: /abs/path/docs/initiatives/2026-11-12-orders/research/plan-review.md

## 2026-11-12 gate
Approved by the user (or: autopilot, posted as status note). Mode: gated|autopilot.

## 2026-11-14 re-gate
Changed: <requirement, scope or new opus/fable work>. Approved by the user.
```

Rulings and decisions made outside a wave (prior-art choices, autopilot rulings, migration answer) go in as `Ruling: <decision> — <reason>`.

Closure, when the initiative ends without completion:

```
Closed: abandoned — <reason>
Closed: superseded — <reason, with the replacing initiative>
```

## Backlog

`docs/backlog.md` holds work discovered along the way: out-of-scope findings, follow-ups, parked review findings, user ideas. One line per item, numbered sequentially:

```
- [ ] B<n> <title> — from <initiative or session> — <date>
- [ ] B7 Paginate the order export — from 2026-11-12-orders — 2026-11-14
```

When a backlog item is planned into an initiative, replace its checkbox with a link to that initiative, keeping the rest of the line:

```
- [2026-11-20-export](initiatives/2026-11-20-export/) B7 Paginate the order export — from 2026-11-12-orders — 2026-11-14
```

Only lines starting `- [ ] ` count as open.

## .gitignore

Add these entries to the project's `.gitignore` when missing:

```
.worktrees/
.tech-lead/
```

`.superpowers/sdd/` ignores itself; SDD manages it.

## Existing docs/superpowers/

A project with documents under `docs/superpowers/` is not migrated silently. Offer once to move them into this hierarchy with `git mv` (a haiku low task: each spec and plan into its own `docs/initiatives/YYYY-MM-DD-<topic>/`). Record the answer in `docs/backlog.md` as a closed item, `- [x] B<n> Migrate docs/superpowers/ — moved|declined — <date>`, so the offer is not repeated. When the user wants it later, record an open item instead.

## Absolute paths

Paths shown to the user are absolute, one per line, never shortened or relative. For example:

```
/home/me/app/docs/initiatives/2026-11-11-orders/mockup.html
```

not `docs/initiatives/2026-11-11-orders/mockup.html` or `./mockup.html`.

- Give the absolute path whenever an artifact is created or updated.
- Every subagent brief asks for the absolute paths of the files it created or changed in its report.
- Gate messages, wave summaries, the finish report and the session-start status list the absolute paths of the artifacts they mention: spec, mockup, plan, ledger, journal, status, ADRs, research reports, logs.
- Paths inside `ledger.json` (`files`) stay repository-relative; only paths shown to people are absolute.
